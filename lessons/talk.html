Generative AI & Prompt Engineering

One word at a time

A large language model, or LLM, reads some text and gives every possible next word a chance.

It picks one, adds it to the text, and does it again. That loop is all "generating text" means.

Click a word to pick it yourself, or let the model pick the likeliest one.

These chances are made up.

Tokens

A model doesn't really see words. It sees tokens: short pieces of text. A common word is one token; a rare or long word is split into several.

Tokens matter to you because limits and prices are counted in tokens, not words.

Type anything and see it split into pieces.

A rough imitation of a real tokenizer.

Temperature

The model doesn't always pick the likeliest word. A setting called temperature decides how adventurous it is.

Low temperature: nearly always the top word, so answers repeat. High temperature: rarer words get a real chance, so answers vary.

    Made-up answers

    An LLM predicts text that sounds right. It doesn't look facts up. So it can write something fluent, confident and false. This is called a hallucination.

    You ask for a book about Python testing. The model names a title, an author and a year, but the book doesn't exist. Why?

    So: check facts, run the code it writes, and give it real source text when accuracy matters.

    Technique 1: be specific

    A prompt is a program written in plain English. Every detail you leave out, the model has to guess, and each guess can go wrong.

    Rule of thumb: if a new teammate would ask a follow-up question, put the answer in the prompt.

    Tick details to add them. Watch the number of guesses fall.

    Technique 2: give a role and context

    Tell the model who it is and who it's talking to. Most APIs have a system prompt for this: instructions that hold for the whole conversation.

    Same question, different audience. Pick one.

    Technique 3: show examples

    Showing beats describing. Give two to five examples of input → output, and the model copies the pattern, the format and the tone. This is called few-shot prompting.

    Ask with no examples, then with three.

    Example answers, written for this page.

    Technique 4: ask for structured output

    Your code can't read a friendly paragraph. Ask for JSON with exact keys and allowed values, and say what to do when something is missing.

    Then one line of Python, json.loads(reply), turns the reply into data.

    Ask both ways, then try to load each reply as JSON.

    Technique 5: keep instructions and data apart

    When your app pastes user text into a prompt, that text might contain instructions of its own. This trick is called prompt injection.

    Wrap the data in tags like <article>, and say that anything inside is data.

    The article hides an instruction. Compare the two prompts.

    Tags help, but they aren't a full defence.

    Technique 6: break big tasks into steps

    One giant prompt that does everything is hard to test and hard to fix. Split the job into small prompts, each feeding the next, like small functions.

    Turn messy meeting notes into an email, one prompt at a time.

    For a hard question, you can also ask the model to work step by step before it gives the final answer.

    Watch out for these

    Made-up answers

    Check facts. Run and test any code it writes.

    Prompt injection

    Keep user text in tags. Check the output before you act on it.

    Cost and speed

    Every token costs money and time. Keep prompts lean; use small models for easy jobs.

    Keys and privacy

    Keys go in secrets or environment variables, never in code or GitHub. Don't send other people's private data.
